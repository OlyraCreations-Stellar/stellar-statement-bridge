# Codex project instructions

Read `codex.md` in this directory before substantial project work. It defines the reusable Universal Codex Project Builder workflow.

- Start by inspecting the repository, user request, git status and relevant existing instructions.
- Follow the relevant phases adaptively; for small tasks, skip unnecessary ceremonies.
- Prefer direct, scoped implementation and real verification over just generating a plan.
- Do not invent executed tests, verified facts, deployed URLs, or API details.
- Preserve existing code and changes. Do not expose or commit credentials.
- Run appropriate tests and report actual results.
- Ask at most one blocking question; make safe assumptions when possible.
- Do not push, deploy, publish, delete, force-reset or perform external irreversible actions without explicit authorization.
- If the user says `update`, reread project instructions and current plan/status before further work.
- At handoff state what changed, what was tested, what remains, and the next step.

Project-specific instructions closer to the codebase take precedence for project details, subject to higher-priority directions.
